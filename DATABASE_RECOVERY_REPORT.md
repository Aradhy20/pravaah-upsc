### Dynamic Table Auto-Synchronization (`scripts/ensure_tables.mjs`):
To prevent catastrophic runtime failures such as the previously observed `Invalid prisma.featureEntitlement.findUnique(): Table public.FeatureEntitlement does not exist`:
- `scripts/ensure_tables.mjs` runs automatically on deployment.
- It queries `information_schema.tables` and executes `CREATE TABLE IF NOT EXISTS` for all missing tables without dropping existing data.
- Verified output: `Found 70 existing tables in database. Newly created: 0. Total tables: 70.`

## 4. Seeding Safety & Data Preservation Rules

A critical requirement is that production deployments must **never overwrite authentic records** or run destructive seeds:

1. **Row Count Guard in `deploy_db_setup.mjs`**:
   ```javascript
   const count = await prisma.question.count();
   if (count === 0) {
     console.log("Database is empty. Seeding authentic records from dump...");
     execSync("node scripts/seed_postgres.mjs", { stdio: "inherit", env: ... });
   } else {
     console.log(`Found ${count} questions in database. Skipping seed.`);
   }
   ```
2. **Idempotent Restoration**:
   - `scripts/restore_postgres.mjs` uses `skipDuplicates: true` and per-record `try/catch` fallbacks.
   - It restores strictly in topological dependency order (`Role` → `User` → `Exam` → `Paper` → `Question` → `QuestionOption` → `Explanation` → `QuestionAnswer`).
3. **Zero Test Contamination**:
   - Production deployment scripts do not inject fake users, simulated student attempts, or mock test results. All telemetry is genuinely generated by real aspirant activity.
